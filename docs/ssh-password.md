# SSH: пароль root и вход по ключу

В главном меню есть **SSH: включить пароль root (ключи сохранить)**.
Прямой запуск из локальной копии скрипта:

```bash
bash kto.sh ssh-password
```

Или из полного репозитория без скачивания helper-файла:

```bash
sudo python3 scripts/kto-ssh-password.py
```

Режим предназначен для Ubuntu/Debian с работающим OpenSSH и systemd. Нужны root,
Python 3.10+ и интерактивный терминал. APT, оптимизация и миграция SSH перед этим
режимом не запускаются. На сервере ничего не меняется от одного обновления KTO.

## Что Меняется

- После подтверждения `ENABLE` прежний пароль **root** заменяется случайным паролем
  из 28 символов: буквы обоих регистров, цифры и специальные символы.
- В конец `/etc/ssh/sshd_config` добавляется управляемый `Match User root` с разрешением
  пароля и public key. Достаточно одного способа, ключ и пароль вместе не требуются.
- Используется `systemctl reload`, не restart. Порт и ListenAddress не меняются.
- Создаётся `/etc/kto-ssh-password.enabled`: следующая оптимизация KTO сохраняет
  выбранный способ входа вместо возврата к root key-only.

Ключи не создаются, не переносятся и не удаляются. Если для root ещё не был настроен
подходящий ключ, этот режим его не добавит. Вход других пользователей, UFW, Fail2ban,
списки разрешённых IP, DNS и маршруты не изменяются. Учётная запись root с запрещённой
оболочкой или истёкшим сроком действия автоматически не исправляется.

**Пароль выводится один раз только в терминал**, не попадает в аргументы процессов,
лог KTO или файл с открытым паролем. В `chpasswd` он передаётся через stdin.
Перенаправление stdout в файл/pipe запрещено; запись терминала внешними программами
мастер контролировать не может. Повторный запуск снова заменит пароль.

## Проверки И Откат

Перед изменениями проверяются синтаксис SSH, работающий service и возможность reload.
Нестандартные параметры запуска `sshd -f/-o` требуют ручной проверки. Кандидат проверяется
через `sshd -t` и `sshd -T -C`: root должен получить оба способа входа, остальные
параметры (в том числе порт и пути ключей) должны сохраниться. Проверяются loopback,
контрольный адрес и текущий `SSH_CONNECTION`, если он доступен.

Конфликтующий ранний `Match`/`Include` не переписывается автоматически. При наличии
AllowUsers/DenyUsers/AllowGroups/DenyGroups мастер также просит сначала проверить
правила вручную. Проверки не охватывают все возможные адреса клиента, PAM-ограничения
и внешний firewall: окончательная проверка входа выполняется из нового SSH-окна.

Резервная копия создаётся в `/var/backups/kto-ssh-password/<дата>-<суффикс>/`, доступна
только root. Она содержит прежний основной конфиг, прежний **хеш** пароля root и поле
возраста пароля (`root-shadow`), кандидат и прежний marker, если он существовал.
Этот backup чувствительный: не публикуй его.

Если смена пароля, reload или итоговая проверка завершаются ошибкой, мастер пытается
восстановить конфиг, прежний хеш/дату изменения пароля и marker. Ошибки отката явно
показываются. Это не защита от потери питания или SIGKILL посреди операции.

**Не закрывай старую сессию.** После успеха открой новое окно и используй команду,
показанную мастером, с правильным IP сервера. Затем проверь обычный вход по ключу.
Наличие синтаксически корректного конфига само по себе не доказывает успешный вход.

## Основания

Разрешённые параметры `Match`, порядок применения настроек и `AuthenticationMethods`
описаны в [OpenSSH sshd_config](https://man.openbsd.org/sshd_config).
Передача пароля через stdin и режим восстановления хеша `-e` описаны в
[Ubuntu chpasswd](https://manpages.ubuntu.com/manpages/noble/man8/chpasswd.8.html).
