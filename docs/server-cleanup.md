# Удаление HAProxy, Nginx и Docker

Мастер удаляет выбранные прокси и пакеты Docker/containerd. Это **не сброс Ubuntu**
и не удаление всех файлов сервера. Ничего не удаляется без ввода `DELETE`.

## Запуск

В главном меню обоих режимов есть пункт **Удалить HAProxy / Nginx / Docker**.
Внутри можно проверить сервер, удалить весь набор либо выбрать отдельные компоненты.

Из локальной копии репозитория:

```bash
bash kto.sh cleanup
```

Только проверка пакетов, сервисов и слушающих TCP-портов:

```bash
bash kto.sh cleanup-audit
```

Эти команды обходят обычные стартовые миграции, автоочистку диска и настройку режима.
Обёртка устанавливает/обновляет сам мастер в `/usr/local/sbin/kto-server-cleanup`.
Для полностью локального запуска без скачивания helper-файла:

```bash
sudo python3 scripts/kto-server-cleanup.py audit
sudo python3 scripts/kto-server-cleanup.py remove haproxy nginx
```

Нужны Ubuntu/Debian с systemd, root и Python 3.10+. Зависимости автоматически не
устанавливаются. Удаление требует интерактивного терминала, режима `--yes` нет.

## Что Сохраняется

- Пароли, пользователи, SSH-ключи и текущие настройки входа SSH.
- IP, DHCP, Netplan, source routing, DNS и таймеры дополнительных IP/основного выхода.
- UFW, Fail2ban, правила firewall, настройки ядра, GRUB и sysctl.
- Remnawave/Xray, Caddy/SelfSteal и WARP.
- Сертификаты `/etc/letsencrypt`, сайты `/var/www` и журналы.
- Образы, volumes и прочие данные `/var/lib/docker` и `/var/lib/containerd`.

Docker с любыми контейнерами, в том числе остановленными, **не удаляется**:
это защищает Remnawave и другие приложения. При недоступном Docker API, rootless
Docker или сторонних нагрузках containerd мастер также останавливается.
Остановленный Docker автоматически не запускается даже через его socket.
В этих случаях можно выбрать удаление только HAProxy/Nginx, а Docker проверить отдельно.

Удаление Docker останавливает его сеть. Штатный `ExecStop` сервиса
`kto-haproxy-bandwidth` снимает управляемые им ограничения tc. Мастер не выполняет
общий сброс firewall/tc и не меняет IP, маршруты или сетевые конфиги самого сервера.
Оставшиеся данные и оптимизации означают, что этот режим не делает сервер «как новый».

## Порядок Работы

1. Проверяет `dpkg --audit`, наличие пакетов и сервисов, нагрузки Docker и место для backup.
2. Симулирует точечный `apt-get purge`: запрещены установки, настройка отложенных
   пакетов и удаление чего-либо вне выбранного списка. `autoremove` не используется.
3. Показывает план и спрашивает `DELETE`, затем повторяет проверки.
4. Создаёт резервную копию конфигураций, останавливает выбранные сервисы и связанные
   с ними KTO-таймеры. Guard HAProxy помечается отключённым.
5. Удаляет пакеты, переносит оставшиеся конфиги и локальные unit-файлы в backup.
6. Проверяет отсутствие пакетов/процессов, состояние SSH и сетевых таймеров,
   контрольные суммы защищённых файлов. Перезагрузки нет.

При сломанном APT мастер **не** запускает `--fix-broken install`, обновление ядра
или `autoremove`. Сначала нужно отдельно проверить и исправить пакетную систему.
Установленные вручную бинарники, сторонние unit-файлы и cron-задания не удаляются
по поиску имени. Для нестандартных установок нужен отдельный аудит.

## Резервная Копия

Каждая подтверждённая операция получает закрытый каталог
`/var/backups/kto-server-cleanup/<дата>-<случайный-суффикс>/`:

- `configs.tar`: конфиги до удаления; символические ссылки не разыменовываются.
- `residual/`: остаточные конфиги, перемещённые после purge.
- `apt-plan.txt`: проверенный план APT.
- `operation.log`: команды и их вывод.
- `manifest.json`: выбранные пакеты, исходные состояния сервисов, перемещённые пути и результат.

Статус `complete` означает, что финальная проверка пройдена. При `partial` сервисы
могут быть остановлены и часть пакетов уже удалена: автоматической переустановки
нет. Не прерывай APT. После прерывания сначала проверь `dpkg --audit`.

Backup содержит конфиги, **не** образы пакетов или копии Docker volumes. Восстановление
нужно делать вручную: проверить manifest, установить нужные пакеты, выборочно вернуть
конфиги, проверить их синтаксис и только затем запускать сервисы. Не распаковывай весь
архив поверх действующей конфигурации без проверки.
