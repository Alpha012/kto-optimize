# VPS-WARP

В режиме ноды пункт **Установка VPS-WARP** и общая установка используют
[tagashi666/vps-warp](https://github.com/tagashi666/vps-warp).
Отдельный запуск: `bash kto.sh warp`.

Установка автоматическая: русский язык выбирается сам, ввод ключа WARP+
пропускается. Зависимости устанавливаются заранее без вопросов APT и без
установки нового ядра. Установщик запускается без управляющего терминала
с отдельным stdin: он не может прочитать следующие команды из меню KTO.

Вывод виден на экране и сохраняется в логе KTO (обычно
`/var/log/kto-tune.log`). Загрузка ограничена по времени, установщик
останавливается через 15 минут. Требуется работающий systemd на хосте.
Установка внутри контейнера не поддерживается.

После установки KTO проверяет конфиг, CLI, `wg-quick@warp`,
`warp-watchdog.timer` и HTTPS-запрос через интерфейс `warp`: ответ должен
содержать `warp=on` или `warp=plus`. Активный сервис без доступа в интернет
не считается успешной установкой. Профиль Remnawave автоматически не меняется.

Рекомендуемый outbound Xray для этой реализации:

```json
{
  "tag": "WARP",
  "protocol": "freedom",
  "settings": { "domainStrategy": "ForceIPv4" },
  "streamSettings": { "sockopt": { "mark": 255 } }
}
```

В правилах профиля направляй нужные домены на `outboundTag: "WARP"`.
Для установки метки процессу Xray нужны соответствующие права
(для Remnawave в Docker upstream указывает `NET_ADMIN`). Не меняй
маршрут по умолчанию сервера на WARP: эта реализация использует
отдельную таблицу 51820 и метку 255.

Проверка и управление:

```bash
vps-warp
systemctl status wg-quick@warp warp-watchdog.timer --no-pager
vps-warp log
vps-warp rotate
```

Если сервис работает, а проверка Cloudflare не проходит, проверь доступность
UDP к endpoint WARP у провайдера. Смена endpoint не исправляет полный запрет UDP.
