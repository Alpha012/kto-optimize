# HAProxy: доменные бэкенды

В поле backend можно вводить IPv4 или DNS-имя, с портом или без него:

```text
hetz.cdnvideo.work
hetz.cdnvideo.work:443
hetz.cdnvideo.work:8443,192.0.2.7:443
```

Без порта используется 443. Схему `https://`, путь и wildcard вводить нельзя.
ASCII/punycode-домены приводятся к нижнему регистру; завершающая точка допустима.
Одинаковые адреса с одинаковым портом удаляются из списка повторов.

При наличии доменного бэкенда генератор добавляет `resolvers kto_dns` с
`parse-resolv-conf`. HAProxy использует DNS-серверы из `/etc/resolv.conf` и
периодически обновляет адрес во время работы (`hold valid 10s`). Домен сохраняется
в конфигурации, а не заменяется разово на IP. Список самих DNS-серверов читается
при загрузке конфигурации; его изменение требует reload HAProxy.

Используется `init-addr last,none`: недоступный DNS не задерживает проверку config
синхронным libc-резолвингом. Если адрес пока неизвестен, этот backend не готов
принимать соединения до успешного разрешения. Валидный config не означает, что
DNS и сам сервер доступны. IP-only маршруты не получают DNS-зависимости.

Предпочтение отдаётся IPv4. Для маршрутов с закреплённым исходящим IPv4 у домена
должна быть рабочая A-запись; поддержка IPv6-выходов здесь не добавляется.
Одна строка с доменом создаёт один `server`, а не пул всех A-записей.
Для явного пула указывай несколько бэкендов. Разные порты одного имени разрешены.

Это TCP passthrough: домен бэкенда не меняет клиентский TLS SNI/HTTP Host,
не выдаёт сертификат и не добавляет TLS поверх уже передаваемого TLS.
Если у бэкенда есть требования к SNI, клиент должен использовать подходящий SNI.
CDN с HTTP-проксированием не становится универсальным TCP-бэкендом.

Настройки source IP, SNI-фильтра, PROXY v2 и лимитов сохраняются. Доменные маршруты
поддерживаются меню, CLI и форматом маршрутов панели статистики; соответствующие
скрипты на сервере и collector необходимо обновить вместе. Системный DNS и
маршрутизация этой функцией не меняются.

Проверка DNS на сервере: `getent ahostsv4 hetz.cdnvideo.work`.
После применения проверяй состояние backend в диагностике HAProxy.

Основание: [HAProxy DNS resolution](https://www.haproxy.com/documentation/haproxy-configuration-tutorials/proxying-essentials/dns-resolution/)
и [настройки resolvers / init-addr](https://docs.haproxy.org/2.8/configuration.html#5.3).
